CP461 · backend design · v1

How a photograph becomes evidence.

The stitcher's server is one stateless FastAPI process. It validates an upload, runs a classical OpenCV pipeline in memory, and answers with a panorama plus the geometric numbers that prove the alignment was real. This page is the contract the five of us build against.

  • Nine gates is now an admission check plus ten gates. Section 3 of the spec.
  • Fourteen error codes is now eighteen, adding TOTAL_UPLOAD_TOO_LARGE, SERVICE_BUSY, and STITCH_TIMEOUT. Section 9.
  • Ten settings is now twenty, including the concurrency, timeout, and input-budget controls. Section 10.
  • max_output_pixels 25 MP is now 8 MP, because the image travels as base64 inside JSON. Section 7.4.
  • A fixed input size is now a per-request budget derived from the frame count, so eight frames stay usable. Section 5.2.
  • seam_positions_x, a single x per pair, is now seam_lines, a two-point line, because a real seam tilts. Section 8.

System view

Three processes, one hop. The browser talks to the API directly; Vercel never proxies image payloads and the API owns no storage.

02

Layer contract

Each layer has one job and one thing it is forbidden to do. Reviews check the forbidden column first.

LayerOwnsMust never
api/routes.py File count, media types, byte limits, settings parsing, error envelopes Import cv2 or touch pixel data
services/stitcher.py Decode, stage ordering, diagnostics aggregation, request-scoped cleanup Know about HTTP, status codes, or multipart
cv/features.py Detector construction, keypoints and descriptors for one image Decide the image order or the reference frame
cv/matching.py KNN matching, distance metric per detector, Lowe ratio filtering Estimate geometry or reject a pair
cv/homography.py RANSAC estimation, inlier mask, reprojection error Warp anything
cv/warping.py Transform composition, canvas bounds, perspective warp Blend or crop
cv/blending.py Valid masks, exposure compensation, feather seam, border crop Hide a bad alignment behind a soft seam
cv/pipeline.py Multi-image ordering, reference choice, stage timing Contain stage math of its own
core/config.py Every threshold and limit, read from the environment once Be bypassed by a literal in route or stage code

05

Success shape

Diagnostics are not a debug extra. They are the assignment's evidence requirement, so they are part of the response contract and not a log line.

{
  "status": "complete",
  "image": {
    "data_url": "data:image/png;base64,…",
    "mime_type": "image/png", "width": 2400, "height": 720
  },
  "diagnostics": {
    "detector": "SIFT",
    "image_count": 3,
    "image_order": [0, 1, 2],                        // reference frame first
    "keypoints_per_image": [812, 765, 930],
    "ratio_passed_matches_per_pair": [146, 128],
    "inliers_per_pair": [101, 87],
    "inlier_ratio_per_pair": [0.69, 0.68],           // floor 0.25
    "reprojection_error_per_pair": [1.42, 1.88],     // pixels
    "output_width": 2400, "output_height": 720,
    "stage_timings_ms": {
      "decode": 31.2, "features": 418.5, "matching": 12.3,
      "homography": 4.8, "warp": 96.4, "blend": 83.7
    }
  }
}

Why each field is in the contract

  • Keypoints per image tells you whether a frame was too flat for the detector before you blame the matcher.
  • Ratio-passed against inliers separates a descriptor problem from a geometry problem.
  • Reprojection error in pixels is the number the report argues from, and the one the RANSAC tolerance is set against.
  • Stage timings decide whether the demo runs SIFT or ORB on the day.

If base64 in JSON turns out too heavy under profiling, the transport becomes a binary image plus a diagnostics sidecar. The logical fields above do not change.

08

Standing rules

Four commitments that outrank convenience. A pull request that breaks one does not merge.

Rule 01

Never return a distorted image instead of an error.

A warped mess that technically renders is worse than a rejection, because it cannot be graded and cannot be debugged. Reject, and name the pair that failed.

Rule 02

Measure every stage, always.

Timings and inlier counts are collected on the success path too, not only when something goes wrong. The report is written from them.

Rule 03

Nothing survives the request.

No globals, no temp files, no cache keyed by upload. Render Free wipes local disk on restart and v1 is designed so that costs nothing.

Rule 04

Cheap checks run before expensive ones.

Count, media type, and byte size are settled before a single image is decoded, so a bad request never buys CPU time.

09

Deployment

Backend · Render Free

  • Service root backend/, bound to 0.0.0.0:$PORT, health path /healthz.
  • A free instance sleeps when idle. The first request after a sleep pays a cold start, so the demo warms the service before the presentation.
  • Local disk is ephemeral and unused. A restart mid-demo costs one retry, not a data loss.
  • opencv-python-headless only. Pulling the GUI build inflates the image for libraries the server never calls.

Frontend · Vercel

  • Project root frontend/, with VITE_API_BASE_URL pointed at the public Render URL.
  • CORS allows the exact Vercel origin plus the local dev origins, listed rather than wildcarded.
  • Image payloads are never proxied through a Vercel Function. The bundle, payload, and duration limits have not been tested against real demo photographs, and the demo is not the place to find out.
